## 已摸清的整合切入点（设计储备）

1. **统一 MCP 门面**：`src/mcp/server.ts` 是单 server 入口，`src/tools.ts` +
   `tool-names.ts` 是工具注册表。聚合方案：把 qmd search / gitnexus 查询包成
   graft 风格工具注册进去，Agent 只见一个 server、一套协议
2. **对照参考**：`D:\参考项目\01-...\MCP服务与工具\smart-mcp-proxy__mcpproxy-go`
   （Go 版 MCP 聚合器：BM25 工具检索/隔离/审计），其 `retrieve_tools`/
   `describe_tool`/`call_tool_*` 三件套 API 设计值得抄
3. **品牌机制**：上游 trail/graft 双名通过 `TRAIL_INVOKED_AS` 环境变量传播——
   我们的 graft-max 沿用同一机制（`GRAFT_MAX_INVOKED_AS`），fork 越深越要
   遵守"环境变量传递身份"的约定，否则 hooks 后台进程会串味
