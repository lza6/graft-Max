### 2026-11 · Docker 部署落地（Dockerfile.max + compose + E2E）

- **改了什么**：
  - `Dockerfile.max`：MCP stdio + 可选 Dashboard 镜像，多阶段构建（build 装 python3/make/g++
    编译 tree-sitter；runtime 只留 git/ca-certificates/curl），`USER node` 非 root，
    仓库 volume → `/workspace`，联邦后端 `INSTALL_QMD/INSTALL_CCC/INSTALL_GITNEXUS` 开关
  - `docker-compose.max.yml`：dashboard 常驻（端口 24688 + healthcheck 打 /stats +
    qmd-index / max-home 命名卷）
  - `src/mcp/server.ts`：新增 `GRAFT_MAX_LEASH=0`——容器常驻模式关 leash 且 stdin EOF 不退出
    （容器没有 MCP 宿主 stdin，否则启动即退 / 10 分钟自杀）；交互式 MCP 会话行为不变
  - `e2e/e2e-docker.mjs`：真实容器 E2E 六项
- **为什么**：用户要求支持 Docker 部署；容器形态和宿主形态的 stdin 生命周期不同，必须显式区分
- **踩坑沉淀（重要）**：
  - **Docker Hub 直连不通** → 先在 Docker Desktop 配代理（settings-store.json 的
    ProxyHttpMode/OverrideProxyHttp(s)）+ Windows 防火墙放行代理端口
  - **buildkit 构建容器到不了宿主代理**（111 Connection refused）：buildkit 用独立网络命名空间，
    只有 `--network=host` 才能连 `host.docker.internal`。但这样每次构建都要 `--network=host` + 代理参数，麻烦
  - **最终方案（推荐）**：容器内实测 `mirrors.aliyun.com` 与 `registry.npmmirror.com` **直连可达**
    → Dockerfile 默认切国内源，构建不再依赖代理/`--network=host`，apt 从 190s+ 降到 6s
