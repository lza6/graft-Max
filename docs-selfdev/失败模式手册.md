# 失败模式手册（症状 → 根因 → 处理）

> 面向"东西不对了，但我不知道从哪查"的人。按**症状**查，不按模块查。
> 每条都给出：怎么确认（可执行命令）、根因、处理动作、怎么避免再犯。
> 最后更新：v0.28.0-max.10。

---

## A. 工具相关

### A1. `tools/list` 是空的 / 看不到任何 `max_*`

**确认**
```powershell
node dist/cli.js mcp <仓库路径>     # 手动发 initialize + tools/list，看返回
ls <仓库路径>/graft/.graph/wiring.json   # 存在=已邀请
```
**根因**：这是**设计如此**——未邀请的仓库零工具（上下文预算规则，`docs-selfdev/项目约束.md` §2）。
`advertised()` 的判据是 `graft/.graph/wiring.json` 是否存在。
**处理**：在该仓库跑一次 `graft build`（或 `GRAFT_MAX_MCP=1` 下的首次查询自动建图）。
**避免**：新仓库初始化时先 `graft init`/`build`，再谈工具。

### A2. `max_find_docs` / `max_trace_arch` / `max_search_semantic` 不出现

**确认**：面板「联邦后端」卡看三个后端的状态；或 `GET /stats` 的 `fedHealth`。
**根因**：对应后端探针失败（未安装 / 不在 PATH）。没装就不 advertise（不占 schema 预算）。
**处理**：按卡片里的安装命令装；装完点「重试探针」（或等 ≤30s 失败 TTL 到期 + 60s 心跳）。
**注意**：不需要重启 MCP server —— 探针会发 `notifications/tools/list_changed`。

### A2b. 工具在这台机器上"到底有没有被用"（怀疑注册了但没人调）

**一条命令打开黑匣子**：
```powershell
node scripts/log-attribution.mjs              # 按真实仓库 / 测试沙箱分组，逐仓库给出会话数、暴露工具数、调用数
node scripts/log-attribution.mjs --root new-api
```

它会告诉你：哪个仓库起了几次服务、`tools/list` 暴露了几个工具、**实际调了几次**。
典型结论有三种：
1. **暴露了但 0 调用** → 工具可用，是会话里没发起调用（闲聊/配置类任务本来不需要；也可能是 health check）。
2. **未邀请（无 `graft/.graph/wiring.json`）→ 零工具** → 在该仓库跑一次 `graft build`。
3. **调用数很高但全在 `graft-mcpsrv*` / `gm-v2-*` / `trail-test-run-*`** → 那是测试沙箱，
   不是真实使用，别把它算成"用户在用"。

详见 `docs-selfdev/日志归因.md`（首次归因的完整数字与排查顺序）。

### A2c. 项目 `.mcp.json` 里的 `graft` 变成了本机绝对路径（槽位被劫持）

**症状**：项目根 `.mcp.json` 的 `mcpServers.graft` 从 `npx -y @nanonets/graft mcp`
变成了 `node <某处>/dist/cli.js mcp`，旁边还多出 `.mcp.json.bak`。

**根因**（2026-11 实测抓到，已修）：`serverEntry()` 原来只判 `GRAFT_MAX_MCP=1` 就返回
本机路径，而 upkeep 刷新用的是 `mcpServers.graft`（上游槽位）→ fork 抢了上游注册位，
违反 `项目约束.md` §1.5。现在 `serverEntry({slot})` 区分槽位：**只有 `graft-max` 槽位才允许
出现本机路径**；上游 `graft` / `trail` 槽位一律保持上游命令。

**自查命令**：
```powershell
# 本仓库/任意项目：graft 槽位应当是 npx @nanonets/graft，不是本机 dist
node -e "const j=require('./.mcp.json');console.log(j.mcpServers.graft)"
```
**回归测试**：`test/max-slot-isolation.test.ts`（5 条：上游槽位不含本机路径、graft-max 槽位才含、
trail 槽位不占用、端到端两文件产物不同、未开开关时行为不变）。

### A3. 工具调用返回 `isError: true`

先读 `text` 的第一句，它是给人看的：

| 文案开头 | 含义 | 处理 |
|----------|------|------|
| `graft-Max federation: … unavailable — install …` | 后端没了 | 按提示装 |
| `gitnexus mcp timed out after 45s — is the repo indexed?` | 仓库没建架构图 | `npx gitnexus analyze` |
| `gitnexus did not answer within 60s (backend may be hung)` | 后端**假死**（握手成功但 query 永不回） | 重试（负缓存让它更快失败）或 `npx gitnexus analyze` 建索引。**max.13 起端到端 ≤62s 必有回包**，此前会无界挂起 135s+ |
| `后端输出超过 8MB 上限，已中止` | 后端返回爆炸（已被 kill） | 缩小查询 / 改 `limit` |
| `No results found.` / `no hits for:` | **不是错误**，就是没答案 | 换词、换工具（见下） |

**换工具口诀**：找"代码在哪"用 `max_find_code`；找"字面出现"用 `max_find_all`；
找"谁调用"用 `max_trace_calls`；找"文档怎么说"用 `max_find_docs`；找"模块依赖"用 `max_trace_arch`；
不记得关键词只记得意思用 `max_search_semantic`。

### A4. 首查很慢 / 返回"没有代码"

**确认**：面板「建图状态」卡（建图中会显示仓库与已耗时）；`ls <repo>/graft/.graph/building.json`。
**根因**：仓库首次建图。上游阻塞等 90s（agent 的 shell 预算只有 2 分钟）；Max 改成等 20s
（`GRAFT_MAX_FIRST_BUILD_WAIT_MS`），超时就返回"还在后台建、建了 N 秒、稍后重问"。
**处理**：等建完再问一次（别改问法，改问法只会浪费一次调用）；面板能看到真实进度。
**避免**：`graft build` 预热；或把 `GRAFT_MAX_FIRST_BUILD_WAIT_MS` 调到能容忍的值。

## B. 面板相关

### B1. 打开面板 401 `unauthorized`

**根因**：非回环绑定（容器/`0.0.0.0`）强制令牌，或你显式设了 `GRAFT_MAX_UI_TOKEN`。
**处理**：看 MCP server 的 **stderr**（不是 mcp.log）里那行
`[graft-Max] dashboard: http://127.0.0.1:24688/?token=<T>`，点它一次即种 Cookie。
**避免**：容器形态导出 `GRAFT_MAX_UI_TOKEN=<长随机串>` 固定令牌。

### B2. 打开面板 403 `forbidden host`

**根因**：Host 白名单（防 DNS rebinding）。你用域名/局域网 IP 访问了。
**处理**：改用 `http://127.0.0.1:<port>` 或 `localhost`；远程访问请走 SSH 隧道或反代。
**不要**为了图省事删掉 Host 校验——那等于把开发日志公开到网段。

### B3. 面板能开但没有数据 / 一直"失联"

**确认**：`curl http://127.0.0.1:24688/stats`（容器里 `127.0.0.1` 永远放行）。
**根因**：MCP 进程退出了（见 C1/D2），或日志没开（`GRAFT_MAX_LOG` 未设 → `/tail` 为空）。
**处理**：`GRAFT_MAX_LOG=1`；面板的日志区会明确提示"暂无日志，开启 GRAFT_MAX_LOG=1"。

### B4. 会话表里自己的会话不见了 / 显示成别人的

**根因**：历史 bug（max.9 修过一轮）：容器里每个进程都是 **pid 1**，只按 pid 认身份会串行。
现在身份是 `host + pid`，判活规则：同 host 用 `kill(pid,0)`；跨 host 用 `lastSeen` 新鲜度（3 分钟）。
**若仍异常**：清 `~/.graft-max/sessions.json`（会被原子重建），并确认 `os.hostname()` 在各容器里不同。
**相关测试**：`test/devlog-sessions.test.ts`。

### B5. 面板很卡 / `/storage` 慢

**根因**：目录遍历（历史实测 7329ms，因为同步 IO 卡死事件循环）。
**处理**：现在有 30s 缓存 + 并发合并 + 异步遍历；如果仍慢，看「存储」卡里哪个目录特别大
（`qmd 嵌入模型缓存`、`dist/vendor`、`node_modules` 级别），把它移出被统计的路径。

### B6. `GRAFT_MAX_UI_LEGACY=1` 之后页面变旧

**预期行为**：这是新面板（`panel/`）的兼容回退开关，保留一个 release 周期。
**若新面板 404 `panel not built`**：跑 `npm run build:panel`（或 `npm run build`）。

## C. 进程 / 生命周期

### C1. MCP server 莫名其妙没了（10 分钟）

**根因**：stdin-leash（Windows 上宿主崩溃时 stdin 的 `end` 永不触发 → 进程+端口泄漏，曾抓到僵尸占 24688）。
**处理**：交互式会话保持默认（活跃会话不可能 10 分钟没有 stdin 字节）；
**常驻容器必须** `GRAFT_MAX_LEASH=0`（compose 已设）。

### C2. 端口 24688 被占

**预期行为**：面板自动 +1..+9；全忙就软失败（记日志，MCP 完全不受影响）。
**确认**：`Get-NetTCPConnection -LocalPort 24688` 找占用者；面板真实地址看 stderr 那行。

### C3. 每次工具调用都拉起一个进程（历史）

**根因**：ICM 时序曾经是"每次调用 spawn 一个 `icm.exe remember`"（单次实测 3.26 秒）。
**现状**：批量（满 32 行或 60s 一次）+ 5s 硬超时 + 并发 1 + 先落
`~/.graft-max/tool-timeline.jsonl`。`GRAFT_MAX_ICM=0` 关，`=2` 干跑。
**确认**：`test/icm-timeline.test.ts`；或看 `tool-timeline.jsonl` 行数 vs icm 调用次数。

## D. 部署 / 打包

### D1. `npm i -g graft-max` 后功能缺件

**确认**：`npm pack` 后 `tar -tzf *.tgz | grep -E "wasm|queries|panel|viewer"`。
**应有**：9 个 `.wasm`（breadth 语法）、17 个 `.scm`（查询）、`dist/panel/*`、`dist/viewer/*`。
**根因**：`package.json.files` 只列 `dist`——新增的运行时资源必须落在 `dist/` 里（`scripts/build-panel.mjs` 就是这么做的）。
**验证**：`.github/workflows/ci-max.yml` 有一道"打包完整性"检查。

### D2. 容器里面板打不开

**根因**：容器内绑 `127.0.0.1` 时 Docker 的 `-p` 打不进去（DNAT 目标是 eth0）。
**处理**：`GRAFT_MAX_UI_HOST=0.0.0.0`（compose 已设），并且 **宿主侧端口只发布到回环**：
`ports: "127.0.0.1:24688:24688"`。这两条必须成对出现——只改一条就是把面板暴露到网段。

### D3. 容器健康检查失败

**根因**：healthcheck 打了需要令牌的数据端点。
**处理**：一律打 `/healthz`（无鉴权、无数据，compose 已改）。

## E. 数据 / 用户全局文件

### E1. `~/.claude/CLAUDE.md` 或 `~/.claude.json` 被截断/损坏

**根因（历史）**：`writeFileSync` 整写 + 进程被杀/磁盘满 → 实测把 `.claude.json` 从 246KB 截成 852B。
**现状**：所有写入走 `src/util/atomic-write.ts`（同目录 tmp → rename，可选 JSON 校验 + `.bak` 轮转 3 份）。
**恢复**：`~/.claude/CLAUDE.md.bak`（或 `.bak.1`/`.bak.2`）；`~/.claude.json` 还有 Claude Code 自带 backups。
**确认**：`test/atomic-write.test.ts`、`test/max-prompt.test.ts`。

### E2. 不小心 `git add -A` 提交了个人记忆库

**现状**：`.gitignore` 已覆盖 `memories.db*` / `*.db.backup-*` / `.mcp.json` / `.trail/`，
并有 pre-commit 钩子（`scripts/check-forbidden-files.mjs`）拒绝提交。
**新克隆要装钩子**：`npm run hooks:install`（设 `core.hooksPath=.githooks`）。
**若已经推上去了**：`git rm --cached` + **改写历史**（`git filter-repo`）+ **轮换任何泄露过的密钥**。

## F. 验证 / 测试

### F1. `npm test` 出现失败，但代码没动

**先确认基线**：`workflow_status.md` 的 A3（本轮 0 fail）。上游历史上有 ~10 个"本机 flaky"
（云连接/日期/hook 冲突），Max 已修到 0。
**处理**：单独跑那个文件确认是否稳定复现；只有稳定复现才是真回归。
**注意**：测试运行器已做隔离（独立 TMPDIR、`commit.gpgsign=false`、
`GRAFT_NO_TRAIL_SWITCH=1`），但**环境变量仍共享**——你 shell 里残留的 `GRAFT_MAX_*` 会改变测试行为。

### F2. E2E 全绿但功能是坏的

**根因（历史）**：弱断言——只判 `result !== undefined`，后端全挂也能刷 9/9。
**现状**：联邦 E2E 断言内容形状（`qmd://…:line #docid` 正则、`isError` 判失败）；
面板 E2E 断言请求频率/落盘结果/零 `pageerror`；`e2e/e2e-ci-smoke.mjs` 24 条自包含断言。
**纪律**：新增断言若只判"有返回"，评审直接打回。

## G. 一页速查

| 症状 | 第一条命令 |
|------|-----------|
| 工具不出现 | `ls <repo>/graft/.graph/wiring.json` |
| 联邦工具不出现 | 面板「联邦后端」卡 / `curl 127.0.0.1:24688/stats` |
| 面板 401 | 找 stderr 的 `?token=` 那行 |
| 面板 403 | 换 `127.0.0.1` 访问 |
| 首查没代码 | 等建图；面板看「建图状态」 |
| 进程 10 分钟消失 | `GRAFT_MAX_LEASH=0`（容器） |
| 面板端口不对 | stderr 的 `dashboard: http://…` |
| 全局文件坏了 | 找 `.bak` |
| 测试失败 | `node --import tsx --test <单文件>` 复现 |
| 一切都对但结果不对 | 先怀疑断言，再怀疑实现 |
