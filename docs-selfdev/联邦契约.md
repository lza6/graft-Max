# 联邦契约（三个后端 · 输出格式 · 软错误矩阵）

> 三个联邦工具跑在**兄弟后端**的 CLI 上，任何一个挂了都不能影响 graft 六件套。
> 本文是"输出长什么样"和"失败长什么样"的唯一权威。改格式 = 改契约，必须同步
> `test/fed-qmd.test.ts` / `test/fed-robustness.test.ts`。
> 最后更新：v0.28.0-max.10（N5 对齐 CLI 实测格式、N6 三条硬化）。

## 0. 总则（违反即返工）

1. **永不 throw**：所有失败返回 `{ text, isError: true }`，`text` 里必须带**可执行的修复命令**。
2. **输出契约由一处决定**（约束 C5）：同一能力有多条路径（内嵌 SDK / spawn CLI）时，
   格式化只能有一个函数，且两条路径都调它。
3. **子进程硬超时**：qmd 30s / gitnexus 45s / ccc 60s；**stdout 上限 8MB**，超限 kill + 软错误。
4. **stdout 才是协议**：子进程 stderr 丢弃（只用于软错误里的一句摘录）。

## 1. `max_find_docs`（qmd）

**输入**：`{ query: string, limit?: number, collection?: string }`
**路径**：进程内 SDK（默认，2–5ms）→ SDK 缺失时 spawn `qmd search`（293ms 级）→ 都不行就软错误。

**输出契约**（与 CLI 逐字节一致，`formatResults()` 是唯一实现，纯函数）：

```
qmd://<collection>/<displayPath>:<line> #<docid>
Title: <标题>
Context: <上下文>
Score:   <0–100>%

@@ -<start>,<n> @@ (<before> before, <after> after)
<snippet 原文>
```

- 多条命中之间用 **3 个换行**（`\n\n\n`）分隔。
- `:<line>` 只在 snippet 里真的含查询词时出现（否则只有 `qmd://…/path`）。
- 无命中 → 常量 `No results found.`（`isError: false`，**不是错误**）。
- 真实样本固定在 `test/fixtures/qmd-cli-sample.txt`（从 `qmd search` 实跑抓的）。

## 2. `max_trace_arch`（gitnexus）

**输入**：`{ query: string }`
**路径**：常驻 MCP stdio 会话（二次调用 128–200ms）→ 会话起不来时 one-shot 子进程 → 软错误。

**输出契约**：gitnexus 返回的 `content[].text` 原样拼接（`\n` 连接、`trim()`）。
MCP 不为它重新排版——上游格式变了我们就跟着变，**不猜、不改写**。

## 3. `max_search_semantic`（ccc）

**输入**：`{ query: string, limit?: number }`（`limit` 在 schema 侧限幅 ≤ 20）
**输出契约**：命中逐条两段式，条间 `\n\n`：

```
<file_path>:L<start>-<end> (<language>) score=<0.00>
<snippet（截 500 字符）>
```

- 单行命中时写 `L<line>`（无区间）。
- ccc 输出不是 JSON（守护进程首启消息等）→ 把可读文本原样透传，`isError` 跟随退出码。
- 无命中 → `no hits for: <query>`（`isError: false`）。

## 4. 软错误矩阵（用户看到什么 / 该怎么办）

| # | 触发条件 | `text` 骨架（实际前缀） | `isError` | 用户动作 |
|---|----------|------------------------|-----------|---------|
| E1 | 后端未安装（探针失败） | `graft-Max federation: <purpose> unavailable — <installHint>` | true | 按 installHint 装；装完点面板「重试探针」或等 30s |
| E2 | 缺 `query` | `max_find_docs requires a query` / `max_trace_arch requires a query` / `max_search_semantic requires a query` | true | 补参数 |
| E3 | qmd 索引不存在 | `indexRepairMessage(dbPath)`（含 `qmd collection add …` / `qmd update`） | true | 按提示建索引 |
| E4 | qmd 索引损坏 | E3 文案 + `last error: …` | true | 删库重建（提示里给了路径） |
| E5 | gitnexus 超时 | `gitnexus mcp timed out after 45s — is the repo indexed? (npx gitnexus analyze)` | true | 先 `npx gitnexus analyze` |
| E6 | gitnexus 会话提前关闭 | `gitnexus closed before answering — repo not indexed? Run \`npx gitnexus analyze\` …` | true | 同上 |
| E7 | gitnexus 起不来 | `gitnexus not runnable: <err> — <installHint>` | true | 装/修 PATH |
| E8 | gitnexus 返回 error | `gitnexus error: <message>` | true | 看 message（多为查询语法） |
| E9 | 后端输出 > 8MB | `后端输出超过 8MB 上限，已中止`（`FED_OUT_OVERFLOW`） | true | 缩小查询范围（**该后端已被 kill，不会再吃内存**） |
| E10 | ccc 不可用 | `graft-Max federation: semantic search unavailable — <installHint> (<stderr 摘录>)` | true | 装 ccc 并 `ccc init` + `ccc index` |
| E11 | 真·无结果 | `No results found.` / `no hits for: <q> ` | **false** | 换词/换工具（不是故障） |
| E12 | 命中 60s 缓存 | 结果前缀 `[cached, 60s TTL]` | 跟随原结果 | 无需动作；改参数即重算 |

**E11 与 E1 的区别极其重要**：前者是"后端正常但没这个答案"，后者是"后端没了"。
E2E 断言必须能区分（`isError` + 内容形状），否则后端全挂也能刷出 9/9——P3-18 的老毛病。

## 5. 观测面

| 指标 | 取法 | 面板位置 |
|------|------|---------|
| 后端可用性/距今多久/多久后可重探 | `fedBackendHealth()` | 「联邦后端」卡 |
| 结果缓存 hits/misses/evictions/size | `getFedCacheStats()` | 「联邦后端」卡副标题 |
| 探针 TTL | 成功 5 分钟 / 失败 30 秒（`PROBE_OK_TTL_MS` / `PROBE_FAIL_TTL_MS`） | — |
| 后端中途装上 | 探针 `false→true` → `onBackendsChanged` → `KeptListing.refresh()` → `notifications/tools/list_changed` | 客户端自动重拉 tools/list |
| 手动重探 | `GET /reprobe`（只跑 `--version`，绝不执行安装） | 「重试探针」按钮 |
