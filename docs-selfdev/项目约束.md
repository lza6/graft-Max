# graft-Max 项目约束（所有改动必须遵守）

> 定稿于 federation 落地时。上游哲学 + 本机红线，违反任一条即不得合并。

## 1. 身份与兼容

- **graft_* 工具的行为逐字节兼容上游**：名字、输出格式、legacy 别名（graft_ask 等）、
  trail_* 双名，全部原样保留。已有 skill/配置/笔记引用旧名字必须继续工作。
- **品牌走环境变量**（`GRAFT_MAX_INVOKED_AS`），不用模块变量——hooks/后台子进程
  靠继承环境识别身份（见 src/brand.ts 注释，上游铁律）。
- **npm 包名 `graft-max`**，版本号 `0.28.0-max.N`（上游版本 + max 补丁位）。

## 2. MCP 上下文预算（上游核心哲学）

- **未邀请 graft 的仓库 = 零工具**：`advertised()` 为空的 repo，连 max_* 也不 advertise。
  用户级注册会开进每个项目，schema 是每轮都计费的 context，不能塞给不想要的会话。
- 联邦工具后端未安装 → 隐藏其工具（probe 结果进程内缓存），不占 schema 预算。
- `initialize.instructions` 保持 <~1000 字符（上游实测的截断红线）。

## 3. 联邦工具（federation.ts）设计规则

- **永不 throw**：一切失败（后端缺失/超时/未建索引/参数错误）都返回
  `{ text, isError: true }`，text 里带可执行的修复命令。graft_* 工具在兄弟后端
  挂掉时必须照常工作。
- **子进程硬超时**：qmd 30s / gitnexus 45s；拿到答案立即 kill，绝不空烧超时。
- **stdout 才是协议**：子进程 stderr 丢弃；MCP server 的 stdout 只发 JSON-RPC。
- **Windows 现实**：npm 全局 CLI 是 .cmd shim，spawn 需 shell 兜底（先直试，
  ENOENT 再 shell）；子 MCP 握手必须发 `notifications/initialized`，且消息分步写、
  stdin 保持打开（一次性 write+end 会经 cmd shim 丢消息——E2E 实测踩坑）。

## 4. 验证链（每个改动必跑）

```powershell
npx tsc --noEmit           # 0 错误
npm run build              # 构建成功
node dist/cli.js --version # 0.28.0-max.N
npm test                   # 基线：4036 pass / 10 fail（上游本机 flaky，见下）
node e2e/e2e-federation.mjs # E2E 9/9（真实后端，见 e2e/E2E-REPORT.md）
```

**测试基线**：上游在本机即有 10 个 fail（formatUpgradeReport/trail 云连接/
recordUse 日期类/hook 冲突类——环境相关非核心路径）。**净新增失败 = 0** 才算过。
mcp-server.test.ts 的 ALL_TOOLS 含 max_*（GRAFT_MAX_FEDERATED=0 可关）。

## 5. 开发者日志（GRAFT_MAX_LOG）

- 默认**关闭**；`GRAFT_MAX_LOG=1` 开到默认路径 `~/.graft-max/mcp.log`；
  设为路径值（如 `GRAFT_MAX_LOG=D:/logs/gm.log`）重定向。
- 记录内容：server boot（root/version/pid）、每个 JSON-RPC 请求（tools/call 含
  完整入参 JSON）、每个工具调用的输出（clip 2000 字符）+ 耗时 ms + isError、
  联邦子进程 spawn/生命周期。
- 实时看：`Get-Content ~\.graft-max\mcp.log -Wait`（PowerShell tail）。
- 日志写失败静默忽略——日志永远不能拖垮 server。

## 6. Web Dashboard（GRAFT_MAX_UI）

- 默认**关闭**；`GRAFT_MAX_UI=1` 用默认端口 24688，设为端口值自定义（如 `GRAFT_MAX_UI=3000`）
- 只绑 127.0.0.1（永不暴露网络）；端口被占则软失败（记一条日志，MCP 不受影响）
- 页面：`http://127.0.0.1:24688` — 实时日志 tail（2s 轮询）+ 活跃会话表（谁/pid/宿主进程/仓库/请求数/启动时间）
- API：`/tail?n=N`（倒序分块读，不全量加载）、`/sessions`、`/stats`
- 会话注册：server boot 写 `~/.graft-max/sessions.json`（pid/cwd/宿主pid/user/请求数），
  exit 打时间戳，读时清掉 pid 已死的僵尸行

## 7. 日志不无限增大（硬保证）

- **大小滚动**：mcp.log 过 5MB → 改名 mcp.log.1（旧的 .1 直接覆盖删除）。两文件硬上限 ~10MB
- **时间裁剪**：server boot 时清掉 14 天前的日志行（按 `[YYYY-MM-DD` 前缀扫描）
- **会话文件自净**：sessions.json 读时剔除 dead pid，不累积

## 8. 不做清单

- 不动 `src/tool-names.ts` 的词汇表（isRepoTool 精确匹配依赖它）
- 不加付费 API、不加本地大模型依赖（算力红线，见 Agent-Code README）
- 不把联邦工具做成 skills/slash-commands（用户明确排除非自动加载形态）
