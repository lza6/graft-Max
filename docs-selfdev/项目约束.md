# graft-Max 项目约束（所有改动必须遵守）

> 定稿于 federation 落地时。上游哲学 + 本机红线，违反任一条即不得合并。

## 1. 身份与兼容

- **graft_* 工具的行为逐字节兼容上游**：名字、输出格式、legacy 别名（graft_ask 等）、
  trail_* 双名，全部原样保留。已有 skill/配置/笔记引用旧名字必须继续工作。
- **品牌走环境变量**（`GRAFT_MAX_INVOKED_AS`），不用模块变量——hooks/后台子进程
  靠继承环境识别身份（见 src/brand.ts 注释，上游铁律）。
- **npm 包名 `graft-max`**，版本号 `0.28.0-max.N`（上游版本 + max 补丁位）。

## 1.5 与上游的隔离（互不覆盖）

- **Max 永远注册为 `graft-max` id、`node <dist>/cli.js mcp` 绝对路径**（GRAFT_MAX_MCP=1 时），
  绝不写上游的 `graft`/`@nanonets/graft` 槽位——上游的 upkeep 自愈机制会重写自己的槽位，
  两个构建抢一个配置位会互相打架（实测：上游 hooks 把 Max 注册改回 npx @nanonets/graft）
- 上游 `graft init` 行为逐字节不变；Max 的注册只在 GRAFT_MAX_MCP=1 时发生
- **stdin-leash**：Windows 上宿主崩溃可能让 stdin 的 end 事件永不触发 → 进程+端口泄漏
  （实测抓到僵尸 server 占 24688）。防护：stdin 静默 10 分钟自动退出（活跃会话不可能
  10 分钟无任何 stdin 字节）

### 1.6 槽位判定的实现约束（2026-11 补，来自一次真事故）

「绝不写上游槽位」这条红线不能只靠"调用方记得"：

- 任何计算 server 启动命令的函数（`serverEntry` 类）**必须显式知道目标槽位**
  （`slot: 'graft' | 'trail' | 'graft-max'`），不得只看一个开关（`GRAFT_MAX_MCP`）就返回本机路径。
- 事故复盘：开关判断 + 上游槽位写入 = fork 在每次 boot 静默改写项目 `.mcp.json` 的
  `mcpServers.graft` 并留下 `.bak`。回归测试：`test/max-slot-isolation.test.ts`。
- 推论：新增任何"写配置"的路径，先问一句**我这次写的是谁的槽位**。

## 2. MCP 上下文预算（上游核心哲学）

- **未邀请 graft 的仓库 = 零工具**：`advertised()` 为空的 repo，连 max_* 也不 advertise。
  用户级注册会开进每个项目，schema 是每轮都计费的 context，不能塞给不想要的会话。
- 联邦工具后端未安装 → 隐藏其工具（probe 结果进程内缓存），不占 schema 预算。
- `initialize.instructions` 保持 <~1000 字符（上游实测的截断红线）。

## 3. 联邦工具（federation.ts）设计规则

- **永不 throw**：一切失败（后端缺失/超时/未建索引/参数错误）都返回
  `{ text, isError: true }`，text 里带可执行的修复命令。graft_* 工具在兄弟后端
  挂掉时必须照常工作。
- **子进程硬超时**：qmd 30s / gitnexus 45s；拿到答案立即 kill，绝不空烧超时。
- **stdout 才是协议**：子进程 stderr 丢弃；MCP server 的 stdout 只发 JSON-RPC。
- **Windows 现实**：npm 全局 CLI 是 .cmd shim，spawn 需 shell 兜底（先直试，
  ENOENT 再 shell）；子 MCP 握手必须发 `notifications/initialized`，且消息分步写、
  stdin 保持打开（一次性 write+end 会经 cmd shim 丢消息——E2E 实测踩坑）。

## 4. 验证链（每个改动必跑）

```powershell

npm run build              # 构建成功
node dist/cli.js --version # 0.28.0-max.N
npm test                   # 基线：4036 pass / 10 fail（上游本机 flaky，见下）
node e2e/e2e-federation.mjs # E2E 9/9（真实后端，见 e2e/E2E-REPORT.md）
```

**测试基线**：上游在本机即有 10 个 fail（formatUpgradeReport/trail 云连接/
recordUse 日期类/hook 冲突类——环境相关非核心路径）。**净新增失败 = 0** 才算过。
mcp-server.test.ts 的 ALL_TOOLS 含 max_*（GRAFT_MAX_FEDERATED=0 可关）。

## 5. 开发者日志（GRAFT_MAX_LOG）

- 默认**关闭**；`GRAFT_MAX_LOG=1` 开到默认路径 `~/.graft-max/mcp.log`；
  设为路径值（如 `GRAFT_MAX_LOG=D:/logs/gm.log`）重定向。
- 记录内容：server boot（root/version/pid）、每个 JSON-RPC 请求（tools/call 含
  完整入参 JSON）、每个工具调用的输出（clip 2000 字符）+ 耗时 ms + isError、
  联邦子进程 spawn/生命周期。
- 实时看：`Get-Content ~\.graft-max\mcp.log -Wait`（PowerShell tail）。
- 日志写失败静默忽略——日志永远不能拖垮 server。

## 6. Web Dashboard（GRAFT_MAX_UI）

- 默认**关闭**；`GRAFT_MAX_UI=1` 用默认端口 24688，设为端口值自定义（如 `GRAFT_MAX_UI=3000`）
- 只绑 127.0.0.1（永不暴露网络）；端口被占则软失败（记一条日志，MCP 不受影响）
- 页面：`http://127.0.0.1:24688` — 实时日志 tail（2s 轮询）+ 活跃会话表（谁/pid/宿主进程/仓库/请求数/启动时间）
- API：`/tail?n=N`（倒序分块读，不全量加载）、`/sessions`、`/stats`
- 会话注册：server boot 写 `~/.graft-max/sessions.json`（pid/cwd/宿主pid/user/请求数），
  exit 打时间戳，读时清掉 pid 已死的僵尸行

## 7. 日志不无限增大（硬保证）

- **大小滚动**：mcp.log 过 5MB → 改名 mcp.log.1（旧的 .1 直接覆盖删除）。两文件硬上限 ~10MB
- **时间裁剪**：server boot 时清掉 14 天前的日志行（按 `[YYYY-MM-DD` 前缀扫描）
- **会话文件自净**：sessions.json 读时剔除 dead pid，不累积

## 8. 自动初始化 + 全局提示词 + 一键切换

- **自动建图**：GRAFT_MAX_MCP=1 时，任意真仓库（非 ~、非 --dir）首次查询自动建图，
  免手动 \`graft init\`。实现：refresh.ts buildMissingMap 放开 isTrailMapDir 门槛
- **全局提示词注入**：server boot 时把 Max 中文引导块（graft-max:start/end 标记）
  注入 ~/.claude/CLAUDE.md **头部**；GRAFT_MAX_MCP 关掉时自动摘除（max-prompt.ts）
- **一键切换**：\`python scripts/switch-mcp.py max|orig|status\`
  ⚠️ 绝不整写 .claude.json（含大小写重复键 + 主进程随时写它，整写曾把 246KB
  截成 852B）——必须字节级精准替换 graft 条目 + swap 原子写 + 写前 JSON 验证

- 不把联邦工具做成 skills/slash-commands（用户明确排除非自动加载形态）

## 7. Docker 部署约束（2026-11 定稿）

- **镜像定义 `Dockerfile.max` 与上游 `Dockerfile` 物理分离**：上游是 GitHub App（HTTP webhook，
  `dist/app/main.js`），我们是 MCP stdio（`dist/cli.js mcp`）+ 可选 Dashboard。改一个不影响另一个。
- **常驻容器必须 `GRAFT_MAX_LEASH=0`**：容器无 MCP 宿主 stdin，默认 leash 会在 stdin EOF 时
  立刻退出、10 分钟静默再自杀。该开关只影响这两条退出路径，交互式 MCP 会话行为不变。
- **构建必须 `--network=host`**（国内网络）：buildkit 构建容器在独立网络命名空间，
  默认 bridge 到不了宿主代理（实测 111 Connection refused）；host 网络才能到
  `host.docker.internal:10808`。另需 Windows 防火墙放行代理端口入站。
- **联邦后端全部可选**：默认装 qmd（体积小、BM25 无模型），ccc/gitnexus 走 build-arg 开关；
  未装后端由 probe 门控自动隐藏工具，不占 schema。
- **运行身份 `node`（非 root）**，仓库以 volume 挂进 `/workspace`，建图产物写回挂载目录。

## 8. 用户全局文件：一律原子写（2026-11 · max.10 定稿）

- `~/.claude/CLAUDE.md`、`~/.claude.json`、`sessions.json` 等**用户全局文件**一律走
  `src/util/atomic-write.ts`（同目录 tmp → rename，可选 `JSON.parse` 校验 + `.bak` 轮转 3 份）。
- **绝不整写**：历史上把 `.claude.json` 从 246KB 截成 852B、把用户全局规则截成 0 字节都是
  整写 + 进程被杀造成的。`scripts/switch-mcp.mjs` 的字节级替换是唯一例外（它有独立的 JSON 校验）。
- 唯一允许的回退路径：`GRAFT_MAX_UI_LEGACY` 这类**显式开关**，不得静默降级。

## 9. 热路径与后台进程纪律（2026-11 · max.10 定稿）

- **`tools/call` 热路径禁止无界同步 IO、禁止无上限子进程 spawn**：
  - 请求计数走内存累加 + 2s 节流（`devlog.bumpRequests`），退出时 `flushPendingBumps()` 兜底；
  - ICM 时序批量写（满 32 行或 60s 一次、5s 硬超时、并发 1、先落 `tool-timeline.jsonl`）。
- **任何后台进程必须三件套**：超时、并发上限、关闭开关（`GRAFT_MAX_ICM` / `GRAFT_MAX_FED_WATCH` /
  `GRAFT_MAX_FEDERATED` / `GRAFT_MAX_REPROBE_MIN_MS`）。
- **缓存不得是单槽**：多仓库场景（`knownRoots()`）下任何以 root 为键的缓存都必须**分桶**
  （`storageCache` / `sizeCache` 都是 Map），否则 N 个仓库就是 N 倍重复工作。

## 10. 前端与断言纪律（2026-11 · max.10 定稿）

- **前端重写必须功能清单逐项勾销**：先列旧页面全部功能，逐项在新实现里勾掉，再提交。
  （max.9 的"工具耗时卡片静默消失"就是这么丢的。）面板契约测试 `e2e/ui-interact.mjs`
  的 27 条断言里有 6 条专门盯"旧功能还在不在"。
- **E2E 断言不得只判"有返回"**：必须判 `isError === false` **且** 内容形状（正则/字段）。
  UI 必须断言"请求频率"或"落盘结果"，不能只看元素存在。
- **断言不得钉死实现路径**：qmd 有内嵌与 spawn 两条路，断言"其中一条真跑了"，
  而不是钉死某一条（T2 之后内嵌是默认路径，钉死 spawn 等于永远失败）。
- **截图不是证据**：Chromium fullPage + `position:sticky` 会画出错位假象，用
  `boundingBox()` + DOM 顺序做证据；要出图就先置 `position:static`。

## 11. 身份与 `serverInfo.name`（口径说明）

- `initialize.serverInfo.name` 仍是上游的 `graft`（`brand()` 只认 `TRAIL_INVOKED_AS`），
  而工具名是 `max_*`。**这是刻意保持**：`serverInfo.name` 是上游契约的一部分，改它会打断
  依赖该字段的客户端/技能；"我是 graft-Max"的身份通过**版本号后缀 `-max.N`**、
  `instructions` 文案与工具名前缀表达。
- **因此 `name === 'graft'` 被测试刻意钉住**（`test/mcp-server.test.ts:52`、
  `e2e/e2e-federation.mjs:60`），而 Max 身份由版本号正则 `-max\.\d+$` 断言
  （`e2e/e2e-ci-smoke.mjs`、`e2e/e2e-docker.mjs`）。要改 `name` 的话，三处断言 + 本段必须一起改。
