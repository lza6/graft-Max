## 0. 一句话结论

工具**确实在工作**：242 次真实调用记录（真实仓库 157 / 测试沙箱 85），8 个 `max_*` 工具

## 3. 「暴露了但没调用」怎么查（按顺序）

1. **该会话是否加载了全局提示词块**：
   `node -e "const t=require('fs').readFileSync(require('path').join(process.env.USERPROFILE,'.claude','CLAUDE.md'),'utf8');console.log(t.includes('graft-max:start'))"`
   → 期望 `true`（当前实测：**有**，块长 552 字符）。若为 false，检查 `GRAFT_MAX_MCP=1`。
2. **该轮任务是否真需要代码检索**：闲聊、改配置、写文档不会调图谱工具——0 调用是正常。
3. **是不是 health check**：`claude mcp list` 会 spawn 一次 server（boot + initialize + 退出），
   这类会话段天然 0 调用。可以按会话时长区分（日志里 boot 到下一个 boot 的间隔）。
4. **工具是否在客户端工具列表里**：若客户端做了工具延迟加载（deferred tools），
   需要 `initialize.instructions` 里的批取指引（我们已保留 <1000 字符的引导文案）。

## 4. 旧名别名（`graft_*` / `trail_*`）的真相

82 次别名调用全部**成功返回**（`isError=false`），分布：沙箱测试里多是刻意的兼容性断言
（`graft-mcpsrv2-*` 每个会话各打一次 `trail_find_code` + `graft_find_code`），真实仓库里
`Agent-Code` 7 次、`new-api` 2 次、`duck2api-hub` 1 次。

结论：**改名 + 别名策略成立** —— 旧名字的 skill/脚本/客户端继续可用，新名字 `max_*` 是主路径
（161 次 vs 82 次，2:1）。上游原版 `graft` 与我们并存互不影响（各自注册各自的槽位）。
